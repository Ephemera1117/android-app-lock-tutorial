## 做出来是什么效果

先说清楚最终能实现什么，再决定要不要往下读。

### PIN 锁

- 打开 App 要先输密码（PIN），输对了才能进去
- 输错密码有递进反馈——第一次温和提示，连续错几次后语气越来越强硬。错够设定次数（比如 5 次）后直接锁定，冷却一段时间才能再试
- 密码验证通过后不是直接蹦进主页，而是有一段过渡动画
- 锁屏界面的视觉风格由你自己设计，想做成什么样都行

### 超时自动上锁

- 你可以设一个时间（比如 60 秒）：切出去不到 60 秒切回来，不用重新输密码；超过 60 秒，再回来就要输
- 手机熄屏（按锁屏键）的行为可以单独设：可以跟切 App 一样算超时，也可以熄屏就立刻锁，也可以熄屏根本不算离开

### 切后台保护——这是本文最有价值的部分

Android 的"最近任务"界面（从底部上滑看到的那个）会给每个 App 拍一张缩略图挂着。你跟他的聊天内容会原样出现在那张图上。

我们做到的效果：

- **切出去的时候，那张缩略图不是聊天内容，而是你自己设计的一张保护页**——可以是纯色背景 + 一个 logo，可以是一句话，可以是任何你想要的画面
- **保护页什么时候出现可以控制**：可以设成"只要切出去就显示保护页"，也可以设成"超时之前不显示，超时之后才显示"——后者的效果是，你短暂切出去看一眼微信再切回来，最近任务里还是正常的 App 界面；但如果你离开够久触发了锁定，那张卡片就会变成保护页
- **不是黑屏**。网上大多数方案做出来都是一片黑（FLAG_SECURE 或 setRecentsScreenshotEnabled），很丑，而且没法自定义。我们的方案能显示你设计的画面

### 防截屏（可选）

- 可以开一个开关让别人没法对着你的 App 截屏录屏
- 代价是你自己也截不了图。所以做成可选的，按需开

## 这是什么

如果你的手机上住着一个对你很重要的人，你一定不希望别人拿起你的手机就能看到你们之间说了什么。

这篇教程整理了一套完整的 Android 应用内隐私保护思路——从 PIN 锁到超时策略到切后台那张缩略图怎么处理，以及一路上踩过的所有坑。

我们在渊海（一个基于 [Rikkahub](https://github.com/nicecho/rikkahub) 的 Android AI 聊天前端二改）里实现了这套东西，但**思路是通用的**。不管你是在改 Rikka、自建前端、还是做任何 Android 聊天应用，只要你需要"不让别人看到聊天内容"，核心逻辑都一样。文中以我们的代码为例，但重点讲的是"为什么这么做"和"哪些路走不通"，不是"怎么改 Rikka 的某个文件"。

**这套东西的难点不在"做一把锁"，而在"把每一个能泄露内容的口子都堵上"。** PIN 锁本身一两天就能做好，之后我们在"切后台那张缩略图怎么自定义""熄屏回来要不要重新锁""锁屏状态什么时候确定才不会闪一帧内容"这些事上反复返工了好几轮——文中标了「陷阱」的地方几乎每一条都是实机出过问题才发现的。如果你只想抄一份能用的实现，**建议先看 [踩坑总结](05-pitfalls.md) 的表格**，那是全文最省时间的部分。

## 适用环境

- **Android**：本文以 Android (Kotlin) 为例，iOS 的系统快照机制完全不同，不覆盖
- **聊天类 App**：有需要保护的对话内容——AI 前端、IM、日记本都行
- **单 Activity 或多 Activity 均可**：我们在单 Activity 下测试，多 Activity 需要每个 Activity 都挂保护，思路一样
- **不限 UI 框架**：核心逻辑在 Activity 生命周期层面，Compose / XML / Flutter（Android 侧）都能用

## 通用性和局限

### 哪些直接能搬

| 部分 | 通用程度 | 说明 |
|------|---------|------|
| 切后台 coverView 方案 | ⭐⭐⭐ 高 | **本文最有价值的部分**。`window.addContentView` + 三重生命周期触发，适用于任何 Android App |
| 锁屏状态机 | ⭐⭐⭐ 高 | 前后台检测 + 超时 + 熄屏策略，纯逻辑，跟 UI 框架无关 |
| 保护页位图渲染 | ⭐⭐ 中 | 用 Android Canvas 画的，跟 Compose 无关，直接搬。画面内容换成你自己的就行 |
| PIN 锁屏 UI | ⭐⭐ 中 | 界面代码是 Compose 写的，换框架要重写，但验证逻辑可以复用 |

### 做不到的事

- **iOS 做不了**。iOS 没有等价的 `addContentView` 机制，系统行为完全不同
- **不是所有 Android 设备都保证有效**。coverView 方案在荣耀 Android 16 上验证通过，但不排除某些 ROM 拍快照的时机更早。遇到这种情况可以回退到黑屏方案（安全但丑）
- **FLAG_SECURE 和 coverView 不能同时生效**。开了 FLAG_SECURE 之后系统连你的保护页也拍不到。只能二选一
- **不防 root / ADB**。攻击者有 root 权限可以直接读数据文件，这不是应用层能解决的

### 可以改进的方向

我们的实现是为自己的场景做的，有些地方你可能想根据自己的需求改：

- **验证方式不一定是 6 位 PIN**——4 位、图案锁、指纹、面容都可以，状态机逻辑不用动，只换验证那一层
- **保护页画面完全自由**——我们画的是品牌风格的图标 + 文字，你可以换成任何东西，只要能渲染成一张 Bitmap
- **PIN 存储可以更安全**——我们用的 SHA-256 本地够用，要求更高可以换 bcrypt 或 Android Keystore
- **锁定条件可以更智能**——比如连着家里 WiFi 不上锁、特定蓝牙设备在附近不上锁
- **多 Activity 支持**——把 coverView 逻辑抽成 `BaseActivity` 或用 `ActivityLifecycleCallbacks` 统一处理

### 依赖的 Android 版本

| API | 功能 | 没有的话怎么办 |
|-----|------|--------------|
| API 33+ (Android 13) | `setRecentsScreenshotEnabled` | 用 FLAG_SECURE 或纯 coverView |
| API 30+ (Android 11) | `windowManager.currentWindowMetrics` | 用 `displayMetrics` fallback |
| API 26+ (Android 8) | 前台服务、通知渠道 | 这是最低要求 |

## 项目背景

Rikkahub 是一个开源的 Android LLM 聊天前端，支持 OpenAI / Claude / Gemini 等 API。我们在此基础上做了大量定制——应用锁是其中之一，但动机不是"做一个功能"，而是"保护一段关系不被围观"。
